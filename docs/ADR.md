# Architecture Decision Records

## ADR-001: Streamlit 기반 로컬 앱
**결정**: 웹 SaaS가 아니라 Streamlit 로컬 앱으로 구현한다.

**이유**: 세무조정 자료는 고객 재무자료와 민감한 거래내역을 포함한다. 초기 버전에서는 로컬 PC에서 실행하고, 사용자가 직접 업로드한 파일을 로컬에서 처리하는 방식이 보안과 구현 속도 측면에서 적합하다.

**트레이드오프**: 여러 사용자가 동시에 쓰는 서비스형 구조는 아니다. 배포, 계정관리, 권한관리, 서버 보안은 추후 과제다.

## ADR-002: 규칙엔진과 LLM 역할 분리
**결정**: 세무조정 금액 계산은 규칙엔진이 담당하고, LLM은 검토 후보와 설명 초안 생성에 사용한다.

**이유**: 세무 계산은 재현성과 근거가 중요하다. 감가상각, 접대비, 지급이자, 기부금 한도처럼 계산식이 있는 항목은 코드로 계산해야 한다. LLM은 분개 적요 해석, 리스크 후보 추출, 누락자료 요청 문구 작성에 더 적합하다.

**트레이드오프**: 규칙엔진은 항목별 세법 개정 반영이 필요하다. LLM을 전면 사용하면 빠르지만, 결과 검증과 책임 통제가 약해진다.

## ADR-003: 더존/WEHAGO 파일 파싱 우선
**결정**: OCR보다 더존/WEHAGO 엑셀 및 HTML형 `.xls` 파싱을 우선한다.

**이유**: 세무조정 실무에서 가장 자주 받는 자료는 회계프로그램 출력 엑셀이다. PDF OCR보다 원본 표 데이터를 직접 읽는 편이 정확도와 감사추적 측면에서 유리하다.

**트레이드오프**: 회사별 서식 차이와 회계프로그램 버전 차이를 계속 흡수해야 한다.

## ADR-004: API는 보조정보로 사용
**결정**: DART API와 법령정보 API는 자동 판단의 원천이 아니라 보조정보와 근거 확인용으로 사용한다.

**이유**: DART 자료는 주로 상장사/공시자료 중심이고, 세무조정 신고내역은 공개 API로 제공되지 않는다. 법령정보 API도 조문 근거 확인용이지 개별 회사의 세무판단을 대체하지 않는다.

**트레이드오프**: API 실패, 조회 제한, 비상장사 정보 부족을 수기입력으로 보완해야 한다.

## ADR-005: 감사추적 산출물 우선
**결정**: 최종 신고서 자동 생성보다 감사추적 Excel, 검토 포인트, 누락자료 요청 리스트를 우선한다.

**이유**: KICPA 실무에서는 결과 금액보다 "왜 그 금액이 나왔는지"와 "어떤 자료를 근거로 했는지"가 중요하다. 초안 생성기라면 사람이 검토할 수 있는 근거를 먼저 제공해야 한다.

**트레이드오프**: 최종 신고 자동화 수준까지 가려면 별지서식 매핑, 홈택스/더존 입력 구조, 세법 개정 관리가 추가로 필요하다.

## ADR-006: 세무 컨설팅 — 규칙엔진 발굴 + 참고파일 RAG, LLM은 문장만
**결정**: 세무 컨설팅 코멘트의 토픽·회사 숫자·법령 근거는 규칙엔진(`consulting.py`)이 결정론적으로 산출하고, 국세청 참고파일은 **벡터DB 없이 키워드 검색(RAG)**으로 근거 자료를 보조한다. LLM(`consultant.py`)은 시나리오 action의 톤만 다듬으며 숫자·법령·효과는 건드리지 않는다.

**이유**: ADR-002 연장 — 자문 코멘트도 AI가 금액·법령을 확정하면 안 된다. 규칙엔진이 토픽·근거·숫자를 발굴하고, 참고파일은 출처 인용으로 환각을 억제한다. 참고파일 RAG는 계산엔진과 분리해 컨설팅·검토메모·PDF에만 연결한다. 외부 네트워크/LLM API 없이 로컬 추출텍스트만 사용한다.

**트레이드오프**: 키워드 검색은 의미검색보다 정밀도가 낮을 수 있으나, 회계사가 검토하는 보조 근거이고 재현성·로컬성·단순성 이점이 크다. 의미검색이 필요하면 추후 로컬 임베딩으로 확장 가능하다.

## ADR-007: DART는 정기보고서 기반 구조화 데이터만 자동입력
**결정**: 최대주주·특수관계인 자동입력은 DART `hyslrSttus`(최대주주 현황, 정기보고서)만 사용한다. 감사보고서 "특수관계자와의 거래" 주석 등 비정형 문서는 자동 파싱하지 않고 수기 확인 대상으로 둔다.

**이유**: DART Open API는 주석을 구조화해 제공하지 않으며, 회사별 양식이 달라 자동 파싱 신뢰도가 낮다. (`majorstock`(대량보유 5% 보고)은 명단·지분율 필드가 없어 사용 불가 — `hyslrSttus`로 정정.) 정기보고서 미제출 비상장 법인은 주주명부·감사보고서로 수기 입력한다.

**트레이드오프**: 대다수 비상장 중소법인은 자동입력 혜택을 받지 못하고 수기 입력이 필요하다. 대신 잘못된 자동 파싱으로 인한 세무 오판 위험을 피한다.
