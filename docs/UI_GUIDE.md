# UI Guide

## 기본 방향
이 앱은 회계·세무 실무자가 반복적으로 사용하는 업무 도구다. 따라서 마케팅용 랜딩페이지처럼 화려하게 만들기보다, 조용하고 밀도 있는 업무 화면을 지향한다.

## 화면 단계
1. 기본정보: 회사명, 사업자번호, 사업연도, 중소기업 여부 등 입력 + 특수관계인 표(DART 최대주주현황 자동입력·출처구분·지분율 하이라이트)
2. 파일 업로드: 재무제표, 분개장, 고정자산대장, 계정별원장 등 업로드 및 파싱 검증
3. 수기 입력: 자동계산이 어려운 세무조정 보조자료 입력
4. AI 검토 보조: 규칙 기반 검토 큐 확인, 자료요청 문구와 검토메모 초안 생성
5. 계산·검토: 규칙엔진 계산 결과·근거·분개 드릴다운, 전수 검토 체크리스트(검토필요 근거법령·검토포인트), 세무 컨설팅 코멘트 확인
6. 출력: 검토패키지 PDF, 감사추적 Excel, `.taxproj` 저장파일, 추천 별지 확인

## 특수관계인 표 (1단계)
- DART 최대주주현황(`hyslrSttus`)에서 이름·관계·지분율을 자동입력하고, 표(`data_editor`)로 편집한다.
- 출처(DART/수기)를 구분하고, 미리보기에서 DART 행 음영·지분율 합계·30% 초과 지배주주를 시각적으로 강조한다.
- DART는 정기보고서 제출 회사만 제공하므로, 비상장 미제출 법인은 주주명부·감사보고서로 직접 추가한다.

## 검토필요·컨설팅 표시 (5·6단계)
- 검토필요 항목은 근거법령(law.go.kr 검증)과 "조문 핵심 → 이 분개에서 확인할 포인트" 해석을 함께 보여준다. 어조는 "~확인/점검 필요"로 단정하지 않는다.
- 세무 컨설팅 코멘트는 시나리오(대안 옵션)와 국세청 참고파일 근거를 보여주되, 채택·확정은 회계사 판단임을 명시한다.

## 사용자 메시지 원칙
- "미업로드"와 "업로드했으나 파싱 실패"를 구분한다.
- 비개발자가 이해할 수 있는 오류 메시지를 사용한다.
- AI 결과는 "확정"이 아니라 "검토 후보"로 표현한다.
- 금액 계산 결과에는 원천자료, 계산식, 법령 근거를 같이 보여준다.

## 테이블 표시 원칙
- 금액은 천 단위 구분기호를 사용한다.
- 원천 행 번호가 있으면 `파일/시트/행` 정보를 표시한다.
- 검토 필요 항목은 정상 항목보다 먼저 보여준다.
- 대량 분개는 상위 일부만 화면에 표시하고 전체 CSV 다운로드를 제공한다.

## 보안 표시 원칙
- 고객자료가 외부 API 또는 LLM으로 전송되는 경우 반드시 사용자에게 의미를 알려야 한다.
- 로컬 LLM 사용 여부와 Ollama 연결 상태를 사이드바에 표시한다.
- API 키 값 자체는 화면이나 로그에 표시하지 않는다.

## 경고 메시지 예시
- 당기순이익을 찾지 못했습니다. 손익계산서 파일 또는 수기입력값을 확인한 뒤 다시 계산하세요.
- 업로드는 되었으나 파일 형식을 인식하지 못했습니다. 더존 HTML형 `.xls` 또는 손상 파일 여부를 확인하세요.
- DART 조회에 실패했습니다. API 키, 네트워크, 조회연도, 비상장사 여부를 확인하세요.
- AI 검토 보조 결과는 세무조정 확정값이 아닙니다. KICPA 검토 후 반영하세요.

## 지양할 표현
- "AI가 세무조정을 완료했습니다."
- "자동 신고 가능합니다."
- "오류 없음"처럼 검증 범위를 초과하는 표현
- 근거 없는 확정적 세무판단
