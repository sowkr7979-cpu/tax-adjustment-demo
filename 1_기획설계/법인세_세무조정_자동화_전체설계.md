# 법인세 세무조정 자동화 시스템 — 전체 설계

> 회계 프로그램(더존 Smart A·WEHAGO 등) 재무자료를 업로드하면, **분개장 집계 + 규칙 엔진**이
> 세무조정을 자동 계산하고, 로컬 LLM이 애매한 분개의 검토를 보조하는 로컬 AI 시스템.
>
> **집계·규칙 엔진(핵심)**: 분개장 1회 순회 집계 → 법령 산식으로 세무조정 금액·과세표준·세액 확정 (4만 건도 1초 내)  
> **LLM(선택 보조)**: 규칙이 판단하기 애매한 분개만 사용자가 선택해 2차 정밀 분석 (로컬 Ollama)  
> **회계사**: 수기 입력(판단 자료)과 계산 내역 드릴다운으로 검토·확정  
> **감사추적**: 모든 판단·계산 근거를 분개 행 단위까지 기록
>
> ### ⚖️ 제1원칙 — 모든 세무조정은 국가법령정보 기반
> 모든 조정 항목은 `src/rules/legal_basis.py`의 법령 매핑(법령ID·조문번호)을 통해
> **law.go.kr 원문과 연결**되어야 하며, 산식은 사업연도 종료일 시행 법령(efYd) 기준으로 검증한다.
> 법령에 없는 임의 규칙(예: 운행기록부 미작성 시 50% 강제) 사용 금지.

## 1. 전체 자동화 흐름 (Streamlit 6페이지 — 구현 완료)

```
[1. 기본정보]
     DART 검색(동일 상호 다수 → 업종·대표자 표시) → 법인정보·재무·주주 자동 입력
     중소기업 판정 워크시트 (DART 매출액·자산총액 prefill)
     특정법인 판정 (영§42②: 지배주주50%초과 + 임대주업·금융수입50% + 상시근로자5인미만)
       → 기업업무추진비 한도 50%·승용차 한도 400만/500만 자동 적용
     부동산임대업 주업 여부 → 간주임대료(조특법§138) 적용 요건
         ↓
[2. 재무제표 업로드]
     재무상태표·손익계산서·원가명세서·이익잉여금처분계산서
     고정자산대장·분개장·계정별원장·계정별명세서(잔액 자동 분석용)
     → 회계자료 표준화 파이프라인 (§3) 통과 + 진단 리포트 표시
         ↓
[3. 수기 입력]  ← "금액은 분개장에서 자동, 사람은 판단만 입력" 원칙
     이월결손금·전기 유보 (감가상각 부인누계 — 고정자산대장 합계와 자동 대사)
     세무조정 필요자료:
       외화·파생 평가방법 신고 여부 (체크)
       임원 명단 선택(거래처 multiselect) → 상여·퇴직금 자동 집계
         (출처 계정과목 표시: 상여금(판)/제조 등 + 집계 내역·분개 라인 상세)
       업무용승용차 자산별 해당 여부 (포터·화물 등 자동 제외 제안, 법§27의2①)
       지급이자: 이자비용 '전체'를 한 표로 → 채권자불분명·건설자금 체크박스
       업무무관자산: 계정별 명세에서 후보(회원권·콘도 등) 추출 → 수기 체크 (법§28①4호가목)
       가지급금·대여금 분개 체크 (특수관계인 목록 기준 추천 + 가수금 동일인 자동 상계 영§53③)
         → 인정이자(법§52) + 업무무관 가지급금 이자(법§28①4호나목) 동시 연결
       부당행위계산 부인 (법§52, 영§88) — 특수관계인 거래 분개 참고 표 + 시가 차액 입력
       기부금 라인 분류 (특례/일반/비지정 — 키워드 자동 제안)
       재고 평가방법 (①신고방법 vs ②장부방법, 무신고→선입선출)
       징벌적 손해배상 (영§23: 실손해 초과분 or 불분명 시 2/3)
       공동경비 (영§48: 총액×분담비율 초과분만)
       간주임대료 (보증금·차입금·자기자본 ← 계정별명세서 자동 + 출처 표시,
                  건설비상당액·금융수익 — 조특령§132⑤)
         ↓
[4. LLM 분석 (선택)]
     1차 규칙 분류 (계정코드·키워드, 한글 이슈 분류 표시 + 분개 드릴다운)
     → 이슈 분류별 선택 multiselect → 선택분만 LLM 2차 분석
     → 백그라운드 스레드 (페이지 이동해도 계속, 진행률 표시)
     → Level 1 RAG: 이슈 관련 조문을 law.go.kr에서 받아 프롬프트 첨부 ("오픈북")
         ↓
[5. 계산·검토]
     집계(aggregate_journals 1-pass) → 법령 산식 → 별지15호 구조 가산/차감 표
     적수(積數) 계산 (jeoksu.py): 분개 거래 날짜로 일별 잔액 재구성
       — 가지급금(상대방별)·차입금·임대보증금 적수, 기초잔액은 B/S 기초잔액으로 보충
     인정이자: 거래상대방별 계산 (별지 19호 구조) — 약정이자는 이자수익 분개 자동 매칭,
       영§88③ 기준(차액 3억 또는 시가 5%) 미달 상대방 제외
     자동 세무조정 계산 내역 드릴다운 (항목 선택 → '왜 자동조정 되었나' 판정 사유
       + 적용 산식 + 근거 분개 + CSV)
     분개 표는 전표 단위 흰색↔회색 교대 표시 (striped_by_group — 차·대변 묶음 구분)
     법령 근거 원문 expander (law.go.kr 사업연도 종료일 시행 기준)
     세무조정 전수 검토 체크리스트 33항목 (자동계산/검토필요/해당없음 + 분개 드릴다운)
     과세표준 → 세율(사업연도 개시일 기준) → 산출세액 → 최저한세 → 차감납부세액
         ↓
[6. 출력]
     감사추적 Excel (LLM 판단근거·세무조정 계산근거·세액 계산근거)
     프로젝트 파일 (.taxproj) / 추천 별지 서식 목록
```

## 3. 회계자료 표준화 파이프라인 (`src/parsers/normalizer.py`)

> 업로드 파일은 항상 깨끗하지 않다 — 확장자 위장 HTML, 인코딩, 제목 행, 음수 표기,
> 합계행, 회사별 계정명 차이를 모두 이 계층에서 흡수한다. **모든 파일 읽기가 통과하는 단일 관문.**

```
① 포맷 스니핑     확장자 무시, 내용 판별 (OLE2 매직바이트=XLS / PK=XLSX /
                  <html·<table=HTML형 / 구분자=CSV)
② 포맷별 읽기     HTML·CSV는 utf-8→cp949→euc-kr 자동 시도, 가장 큰 표 선택
③ 빈 행·열 제거   원본 행번호는 감사추적용으로 보존 (__row__)
④ 헤더 행 탐지    제목·회사명 행 아래 숨은 실제 헤더를 키워드 매칭(2개 이상)으로 승격
                  (Excel은 1행 헤더 정상 인식 시 그대로 — 기존 동작 보존)
⑤ 진단 메타       포맷·인코딩·헤더 행·행수·제거 행수 → 2단계 UI "파일 표준화 진단" 표시
```

| 현실 문제 | 처리 |
|---|---|
| .xls인데 실제 HTML (구버전 더존) | 내용 스니핑으로 처음부터 HTML 라우팅 (lxml) |
| 음수: `(1,234)` `△1,234` `▲` 후행`-` 전각숫자 `원` | `parse_amount()` 통일 변환 |
| 합계행 vs 계정행 | `is_total_row()` — 합계·소계·`...총계` 태깅 (당기순이익·기계장치 오탐 방지) |
| 계정명 동의어 | `expand_keywords()` — 접대비↔기업업무추진비, 매출액↔영업수익 등 |
| 계정코드 없는 보고서형 | 분개장 계정명→코드 다수결 역보충 |

검증: 단위테스트 29건 + 티엘 실데이터 회귀(분개 49,060건 수치 일치) +
결산부속명세서.xls 제목 6행 아래 헤더 자동 탐지 성공.

## 4. 1차 규칙 분류와 LLM 역할 분리

- **1차 규칙 분류** (`classifier.py`): 계정코드·키워드로 전체 분개 100% 분류, 한글 이슈 분류 표시
- **LLM 2차** (`llm/analyzer.py`): 사용자가 **이슈 분류별로 선택한** 분개만 배치 분석
  - 로컬 Ollama (현재 gemma4, CPU ≈ 1건/분 — 예상 소요시간 표시)
  - Level 1 RAG: `ISSUE_TO_ARTICLE` 매핑으로 관련 조문을 프롬프트에 첨부 (환각 방지)
  - 백그라운드 스레드 — 페이지 이동해도 계속 실행
  - 관용 파싱: 모델이 임의 코드 반환 시 UNKNOWN으로 보존 (결과 유실 방지)
- **LLM이 절대 하지 않는 것**: 손금불산입 금액 확정, 한도·과세표준·세액 계산

상세: `LLM_분개전체분석_설계.md`

## 5. 세무조정 규칙 엔진

### 5-1. 분개장 집계 (`aggregator.py` — 더존식 1-pass)

기업업무추진비(카드/문화/전통시장/증빙불비), 벌과금, 법인세비용(차변만),
외화환산·파생·유가증권 평가손익, 충당금 당기 설정액, 수입배당금, 차량비,
이자비용 총액, 가지급금·대여금 라인을 한 번 순회로 집계.
**항목별 매칭 분개를 `detail_lines`에 보관 → 계산 내역 드릴다운.**
`sum_related_party_revenue()`: 매출 분개의 거래처를 특수관계인 목록과 대조 →
특수관계인 수입금액 (접대비 한도 ×10% 반영).
증빙 정보가 아예 없는 분개장(WEHAGO)은 증빙불비 판정을 건너뛰고 "판정 불가" 표시.

### 5-1b. 적수(積數) 계산 (`jeoksu.py`)

분개 거래 날짜로 일별 잔액을 재구성해 **실제 적수**를 계산한다 (잔액 × 365 근사가 아님).
**원칙: 모든 적수는 B/S 기초잔액 + 분개장 당기 증감의 일별 계산.**

- `jeoksu_from_deltas(거래증감, 기초잔액)`: 일별 잔액 × 경과일수 합계 (음수 구간 0 처리)
- `account_jeoksu(분개장, 계정 키워드, 기초잔액)`: 계정 단위 적수
  — 기초잔액은 재무상태표 '기초잔액' 컬럼에서 자동 (`_bs_amount_detail(column="기초잔액")`)

| 적수 항목 | 기초잔액 | 당기증감 |
|---|---|---|
| 가지급금 (상대방별, 영§89⑤) | B/S 가지급금·대여금 기초잔액 자동 prefill (수정 가능) | 체크 분개 일별 + 동일인 가수금 상계 |
| 차입금 (영§53②, 조특령§132①) | B/S 기초잔액 | 차입금 계정 분개 일별 |
| 임대보증금 (조특령§132⑤) | B/S 기초잔액 | 보증금 계정 분개 일별 |
| 건설비상당액 (조특령§132⑥) | B/S 건물·구축물 기초잔액 | 분개 일별 × 임대용 비율(입력 건설비 ÷ 기말 건물가액) |
| 업무무관자산 (영§49·53) | 체크한 계정별 B/S 기초잔액 | 해당 계정 분개 일별 (계정별 산정 방식 표기) |

분개에 변동이 없으면 기말잔액 × 일수로 폴백하고 계산 내역에 출처(일별 계산/근사)를 항목별 표기.
