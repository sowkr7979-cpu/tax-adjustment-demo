# 3단계 수기입력 — 건별(件別) 질문형 재설계

> **개정 이력**: 초안 → KICPA 설계리뷰·law-compliance 법령리뷰(efYd=2024-12-31) 반영 (v2).

## 1. 문제 정의

현재 3단계 수기입력은 상당수 항목이 **총액(總額) 1칸 입력**이다
(예: "부당행위계산 부인액 ___원", "외화환산손실 ___원").

회계사 실무 관점의 한계:
- **소득처분 구분 불가** — 같은 항목이라도 건별로 처분이 다르다(부당행위 1건 배당·1건 상여·1건
  기타사외유출). 총액 1칸이면 별지15호 소득처분란을 채울 수 없다(영§106).
- **근거·증빙 구분 불가** — 어떤 건이 어떤 법령·증빙인지 추적 안 됨. 감사추적이 "총액, 사유:수기"로 부실.
- **무엇을 입력할지 모름** — "그냥 금액을 가져다 입력"은 회계사가 각 건의 조정대상 여부·필요자료를
  스스로 판단해야 해 누락·오류 위험.

→ **건별로 붙이고, 각 건마다 질문으로 필요자료를 결정**하는 방식으로 전환한다.

## 2. 설계 원칙

1. **단위 우선(건별이 기본, 단 항목 특성에 맞는 단위)** — 분개 후보 건을 행으로 제시하고 건마다
   분류·처분·자료를 결정한다. 단, 항목 성격에 따라 **단위가 다르다**(아래 §4):
   `per-line`(분개 건별) / `per-officer`(임원 1인별) / `per-category`(재고 종류별) / `per-item`(항목 1회).
2. **질문 기반 결정(decision tree)** — 예/아니오·선택형 질문을 순서로 던져 답에 따라 **필요한 추가자료만**
   노출(`show_when`). 조정대상 아님 → 즉시 닫힘. 법령 요건 게이트(예: 영§88③)는 자동 분기로 막는다.
3. **coverage.py 연계** — 전수 체크리스트(33항목)의 매칭 분개(`lines`)·필요자료(`need`)를 카드 입력으로 재사용.
4. **점진 전환** — 본질적 항목/기간 단위(이월결손금·비과세·세액공제)는 유지, 처분구분 실익이 큰 항목부터.
5. **판단은 회계사(ADR-002)** — 시가·업무관련성은 회계사 선택. 시스템은 답을 산식·처분·별지행으로 연결만.
6. **법령 게이트 필수** — 법령에 요건이 있으면(영§88③ 3억/5%, 영§45 열거, 영§76 화폐성·신고) 질문 흐름에
   게이트로 반영. 법령에 없는 임의 요건(예: 지급대상 우선판정)을 1차 질문으로 두지 않는다. (law-compliance 반영)

## 3. 질문 스펙 데이터 모델 (선언형)

```python
@dataclass(frozen=True)
class Question:
    id: str; text: str; kind: str            # yesno|select|amount|counterparty|date
    options: tuple = (); help: str = ""
    show_when: tuple = ()                      # (답id, 기대값) 모두 충족 시 노출 (decision tree)

@dataclass(frozen=True)
class DispositionRule:                         # 답 → 소득처분(영§106)
    by_question: str; mapping: dict; default: str = "검토필요"

@dataclass
class ReviewItemSpec:
    key: str                                   # coverage 항목명 연계 키
    legal_basis: str
    unit: str                                  # "line"|"officer"|"category"|"item"  (← per_line 대체)
    questions: list[Question]
    amount_fn: Callable[[dict], int]           # 답 → 조정금액(0이면 행 미생성)
    disposition: DispositionRule | None
    add_or_deduct: str                         # "add"|"deduct"
    target_label: str
    # ★ 을표 연계 (KICPA 리뷰 #4 — 가장 큰 구멍 보완):
    reserve_field: str | None = None           # 유보성 결과를 합산할 TaxAdjustmentResult 집계 필드명
                                               #   (예: 재고 inventory_adjustment, 외화 forex_*). None이면 사외유출/기타.
    gate_fn: Callable[[dict], bool] | None = None  # 법령 요건 게이트(영§88③ 등) — False면 조정 제외
```

### 3-1. 건별 결과 → 별지15호 → 자본금과적립금(을) 연결 스펙 (필수)

KICPA #4 지적: 건별 처분이 별지15호·을표로 흐르는 경로가 비어 있었다. 보완:

```
건별 답(answers) ──amount_fn/gate_fn──▶ LineResult(금액, 처분, 근거, 분개ref, reserve_field, add/deduct)
        │
        ├─(요약)─▶ summary_rows.adjustment_rows : 처분별 집계 행 (신고서 표시용)
        ├─(드릴다운)─▶ 감사추적 : 건별 근거·분개ref (회계사 서명용)
        └─(을표)─▶ reserve_field 가 있으면 그 금액을 TaxAdjustmentResult 집계 필드에 합산
                   → reserve_status.build_reserve_status 가 그 필드로 자본금과적립금(을) 유보 행 생성
```
- **유보성 건별 항목**(재고·외화·건설자금·평가)은 반드시 `reserve_field`로 기존 집계 필드에 합산되어야
  을표에 반영된다. 사외유출·기타 처분 항목은 `reserve_field=None`.
- 별지15호는 **요약=처분별 집계 행 + 드릴다운=건별**을 모두 제공(KICPA ❓2 권고).

## 4. 항목 분류 (개정)

### (A) 이미 건별 — 공통 프레임으로 표준화 (unit=line)
지급이자 분류표 · 기부금 라인분류 · 가지급금/대여금 라인체크 · 업무무관자산 계정체크
**＋ 징벌적 손해배상금**(현행 라인체크 존재 — A로 편입, law/KICPA 반영).

### (C) 항목/기간·세액 단위 — 건별 제외 (현행 유지)
- 이월결손금(연도별)·비과세소득·소득공제(법§13①)·전기유보 명세·세액공제·가산세·기납부.
- **토지등 양도소득에 대한 법인세(법§55의2)** — KICPA 🔴2·law 🟠: **소득처분(영§106) 대상이 아니라 산출세액
  추가** 항목. §4(B)에서 제외하고 **세액 단계**에 둔다(현행 위치 유지). 양도소득=양도금액−장부가액(법§55의2⑥)
  산식은 입력 help로 안내하되 **양도소득 금액 자체는 회계사가 직접 입력**(자산별 장부가액·취득가액 명세가
  분개에서 자동 산출되지 않으므로). 미등기 제외사유(영§92의2④)는 미등기 체크박스 help로 안내해 회계사가 판단.

### (D) 별도 트랙 — 명시만, 건별 프레임 비대상 (KICPA ❓4)
- 공동경비 분담초과(영§48) — 공동사업자별 분담기준 초과(현행 총액, B 후보로 검토).
- 합병·분할(법§44~47) — 적격여부·승계가 복잡, 건별 부적합 → 별도 검토 트랙.
- 국고보조금·공사부담금(법§36~37)·보험차익 일시상각(법§38) — 일시상각충당금(유보, 을표 연계) 누락 보완 대상.

## 6. 구현 계획

1. **공통 프레임** `src/ui/review_questions.py` — 데이터모델·순수로직(완료) + 렌더러
   `render_item_card(spec, lines, store)`(streamlit). 답은 `ManualInput.review_answers: dict`(.taxproj 직렬화).
2. **(A) 표준화** — 기존 4개 분류기 + 징벌적손배를 공통 프레임으로(동작 동일, UI 통일).
3. **(B) 전환** 우선순위: 부당행위(금전대여 제외·3억/5% 게이트) → 자산수증·채무면제 → 임원 상여/퇴직(officer)
   → 복리후생(열거 게이트) → 재고(category)/외화(토글) → 의제배당.
4. **연결**(§3-1): 건별 결과 → `summary_rows` 처분별 행 + `disposition` choices + 유보는 `reserve_field`로
   `tax_result` 집계필드 → `reserve_status` 을표.
5. **회귀**: 페이지 렌더 스모크 + **건별→집계 금액이 종전 총액 입력과 일치**하는 단위테스트 + 게이트 단위테스트.
